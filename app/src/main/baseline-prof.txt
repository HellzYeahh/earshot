# Earshot's own ART baseline profile (hand-written, 1.0 performance pass CO1 / ST1).
# =============================================
# Why: the libraries (Compose, navigation, lifecycle, ...) ship their own rules, but no rule
# covered dev/earshot, so every Earshot class on the start path ran in the interpreter or the
# JIT until the phone's background dexopt reached it. That happens about a day after each
# install or update. Sideloaded GitHub / F-Droid installs never get Play cloud profiles, and
# the Play closed test has too few users for one to form. AGP merges this file with the
# library rules for both flavours. In release builds R8 expands the wildcards and rewrites the
# names it obfuscates; the result ships as assets/dexopt/baseline.prof. On a Play install ART
# compiles it at install time. On a sideload ProfileInstaller (already in the APK through
# Compose, activity, lifecycle and navigation) hands it to ART at the first start, and it is
# compiled at the next idle dexopt. Debug builds are never profile-compiled.
#
# It only changes what ART compiles ahead of time (H), marks as startup (S) or post-startup (P) code and puts in
# the app image (class lines). It never changes behaviour. A stale rule is harmless: a class
# that moved simply stops matching.
#
# Scope: the process start, the root composable and the first screens, nothing else. Left out
# on purpose: the vendor wire stacks (BMAP, Bragi, Soundcore, ...). A connect is waiting on
# Bluetooth there, not on the CPU. Also left out: Sound, Tools, More, the Lab, demo devices
# and the night-time Sleep runtime. Add them only after measuring, because every rule makes
# the on-device odex and the install-time dexopt bigger.
# Generating the profile with a Macrobenchmark module (ST1 / SI0) would replace this file.
#
# Syntax (one rule per line, '#' starts a comment line):
#   method rule:  FLAGS + class descriptor, an arrow, then name(params)return
#   class rule:   the class descriptor alone (L, slash-separated name, semicolon)
#   FLAGS:        H hot (compiled ahead of time), S used during startup, P used after startup
#   wildcards:    two stars = any characters including the package slash;
#                 one star  = any characters except the slash. That still takes Kotlin's
#                 $-nested classes, Compose lambdas and the FooKt file classes.
# A mistyped rule is dropped silently, so check the build output after changing this file:
#   app/build/intermediates/merged_art_profile/<variant>/merge<Variant>ArtProfile/baseline-prof.txt
#     must contain these dev/earshot lines;
#   app/build/intermediates/r8_art_profile/<variant>/expand<Variant>ArtProfileWildcards/baseline-prof.txt
#     must list concrete dev/earshot methods and classes;
#   the release APK's assets/dexopt/baseline.prof must grow (9.2 KB before this file).
