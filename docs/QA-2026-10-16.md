# QA walkthrough — 2026-10-16, emulator (API 37), demo mode

Full screen-by-screen pass over the debug build using the built-in virtual QC Ultra 2 (so every
control really round-trips through the connection manager, frame buffer, protocol layer and UI).
Screenshots were kept outside the repo (`build/qa/`).

**Result: no crash at any point** (`AndroidRuntime` stayed empty across ~140 interactions, rotation,
dark mode, kill-and-relaunch).

## Verified working
- Home: all mode chips (`[31.3] START` + `[31.10]` re-read), favourites (`[31.8]`), noise slider
  (`[31.10]` with the inverted wire byte), Wind Block, ANC on/off (slider greys with a hint),
  Immersive Audio Off/Still/Motion, refresh (full re-read incl. the 11-slot `[31.6]` dump).
- Edit modes: 4 locked presets, slot 5 saved as "Train" (40-byte `[31.6]` SET_GET), usable from Home.
- Sound: headphone EQ (`[1.7]` per band, debounced), Pro EQ enable (paused on the speaker with a
  banner), presets, graphic + parametric editors, Auto preamp, save/delete preset, AutoEq import,
  boost warning above 6 dB, 3 dB cap with limiter off, global-session switch, per-app profile.
- Tools: codec panel without Shizuku (banner + Developer options), mic check (records and plays
  back, says which mic), Lab scan of blocks 0/1/2/31 with names + copy.
- More: sidetone, auto play/pause, auto-answer, multipoint, devices (switch with the documented
  routing retry, pairing mode), voice prompts + language, power off, automations of every trigger
  type (OnConnect fired on every reconnect), preferences, demo toggle both ways, About credits.
- Notification: battery/mode + mode buttons; tapping a button switches the mode.
- Landscape and dark mode on every tab; kill + relaunch restores everything app-side.

## Fixed after the walkthrough
- Shortcut-button actions decoded wrong (little-endian mask) → protocol fixed; picker always offers
  the current action and Disabled.
- Demo power-off never reconnected → the demo loop now reconnects by itself.
- Demo battery drained to 1 % and raised the low-battery alert → 1 %/15 min with a 35 % floor.
- Dialogs shifting under the keyboard, "Custom" state unlabelled after a manual tweak, duplicate
  Developer-options button, selected chip off-screen, limiter-off hint, Samsung-only note,
  plural, redundant caption, automations re-sorting, FAB under the snackbar, truncated device name.
- Demo rename now answers error 5 like the real firmware, so the "Bose locks this" path is exercised.

## Known, left as is
- The virtual unit's own state (custom slots, battery) lives in memory: it resets when the process
  restarts. App-side state (presets, rules, preferences) persists. Demo-only.
- After a mode switch the simulator pushes an unsolicited `[31.10]` in addition to answering the
  GET, so the log shows two identical STATUS lines. Harmless.
